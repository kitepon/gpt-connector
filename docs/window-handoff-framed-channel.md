# Unpublished framed SessionPort composition

This candidate composes the accepted TS v2 byte codec with the existing Promise client. It is not imported by the CLI and has no pipe implementation. The exact Windows source is `quolu/OL-RemoteWindow@30aea928ae2909eae10f92ea7e8e898e4b38a2be`, especially `WindowHandoffFramedSessionModel.cs`, `WindowHandoffFrameV2Codec.cs` and the fixed SessionPort declaration.

`AuthenticatedFramePipe` must be supplied by the native owner: one already authenticated opaque session, its initial host registration, original EOF/subscription lifecycle, same-channel writes and native watch lifetimes. The adapter neither authenticates an OS principal nor issues a watch-ready signal. Missing/mismatched lifetime is a protocol failure. The adapter reserves one framing namespace per opaque session, owns its public session fields and binds the supplied methods before later use.

The client sends hello, strictly receives welcome with the initial registration, sends ready and strictly receives the complete ready_ack with the same registration. It becomes established only after its own whole ready write and the complete ACK receipt. Duplicate/out-of-order frames, wrong registration, partial ACK/timeout and stale sessions cannot admit a request. On the Host, `ReadyAckWriteCompleted` and the owner queue are still the Windows provider's responsibility: it must complete the ACK write before opening request processing. The client receiving bytes is not an independent proof of that Host callback; the in-memory fixture explicitly supplies that ordering.

The original Promise client retains the request's private token across all RPCs. At each exchange it passes that token's remaining raw deadline/cap. The framing adapter captures that exact cap once with `startBoundedWait`, using the same clock implementation and its private budget mechanism. That subordinate token is never renewed: sender queue time is consumed before `prepare` at the actual write boundary, the cap is floored there and the raw deadline remains unchanged. `startBoundedWait` uses min(cap, raw remaining) on its first monotonic observation, without turning a relative cap into a corrected epoch. It cannot increase the caller's sampled remaining budget. The caller's original token and final-admission checks remain authoritative; transit time and simultaneous peer termination are not claimed.

`pipe.write(prepare)` may invoke prepare exactly once at the real write boundary. Preparation checks the same token, original request abort and terminal state, then snapshots the final v2 bytes. Before that boundary the client can retain NotSent; after it, an uncertain result is Unknown. A provider's post-boundary NotSent claim seals with Unknown. A complete write result is required before a received reply is published. No write retry, reconnect or new session is available. Cleanup gets its independent original token/cap and no original abort signal. Late queued preparation after timeout/abort cannot emit the former request.

Original request/reply/control bytes, wait fields and lifetime tuple are retained as owned snapshots. The four RPC JSON bodies and v2 header are unchanged. Call IDs are strictly increasing per session, replies are single-use and outcome/reference/watch must match the original request. A begin record exists even when its write is NotSent, so mode-begin cancellation reaches the same-session original call. Only exact cancelled ACK reaches the existing receipt map's confirmed state; error/effect-none, EOF or close completion cannot prove owner reclamation. The Windows owner queue/tombstones remain the provider's responsibility and the fake owner is marked as synthetic.

The adapter subscribes before handshake/begin, retains a first watch-loss tuple even before armed and routes original native invalidation signals. Loss/cancel cannot revive an old armed reply. EOF seals all pending calls and the namespace. Native provider cleanup must happen independently of control delivery; the local adapter cannot complete it by closing. Close/dispose failures remain visible as failed/release_failed states with a fixed safe close error.

The new in-memory fixtures exercise partial/full ACK ordering, byte-frame→Promise/input→owner ACK, queue rollback/floor/forward expiry, pre-write abort, NotSent/Unknown, independent cleanup, late armed, first loss, missing native lifetime, stale session/call/registration, bad cancel ACK, EOF and explicit lifecycle failures. They use injected clocks/timers and a fake authenticated pipe/native lifetime/owner. They do not execute actual I/O, timers, OS hooks, FOX, API, notifications, credentials, CLI or release operations. The accepted v2/clock/Promise suites are not rerun.
