# Product byte/pipe boundary for the fixed factory bootstrap

This unpublished module implements `CoreHelperBridge` over a factory-owned `FixedCoreHelperBootstrap` port. It has no default bootstrap, configurable entry path, environment loader, authentication issuer or CLI import. The factory must bind its adopted fixed entry/activation, original fd4 AF_UNIX SOCK_SEQPACKET authority endpoint, direct product parent identity and broker verification. That bootstrap and reverse-direction broker verification remain unimplemented in factory c39393fd.

The product snapshots original frame bytes before invoking the port, serializes the cloned control DTO once, and passes the exact immutable string in `CoreHelperLaunch`. The bootstrap must use that same string as `--core-control-json`; the authority request hashes its exact UTF8 bytes without canonicalizing the control again. Child stdin receives the original frame once, or EOF with no bytes for metadata-only/unconfirmed writes. Dedicated fd3 receives a bounded strict UTF8 JSON object with final newline. No child stdout/stderr content is forwarded into ordinary product output.

The launch declaration fixes reply fd3, authority fd4 and 2500ms. Control/reply are bounded to 16384 bytes and the original frame to 65536. Completion requires stdin finish, fd3 EOF and a clean child close. Missing/partial/oversize/invalid reply, stdout output, process/input error or timeout rejects observation; it does not rerun setup/output or replace its original result. A timeout requests SIGKILL; failed signalling remains explicitly cleanup-unconfirmed. The adapter cannot prove authority by pipe layout or a successful child alone. The existing observer still validates the returned record and retains binding unknown/reporting false/resource false.

Factory c39393fd's new authority adapter has a separate same-run composition defect, GPT-CORE-AUTH-PHASE-1: its phase-specific authority ref changes `activation_provenance_ref`, while the existing helper requires that field to remain identical between begin/result. This product bridge does not bypass that check. The fixed factory bootstrap and that repair are needed before a real helper composition can be accepted.

New tests exercise this byte/pipe boundary with synthetic child streams and bootstrap only. No real helper launch, fd4 authority, kernel authentication, actual issuer/artifact, host, NVM/npm, CLI or public output is executed. Existing serializer/alias/helper suites are not rerun.
