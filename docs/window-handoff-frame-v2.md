# TS local frame v2 source candidate

Windows contract: `https://github.com/quolu/OL-RemoteWindow.git`, branch `codex/window-handoff-contract`, commit `30aea928ae2909eae10f92ea7e8e898e4b38a2be`. The fixture `test/fixtures/window-handoff-frame-v2-synthetic.json` is the unchanged 4607-byte Windows Encode output, SHA256 `65f4ba4a40f741a34c890bd0bf5ef5b472441f0435bae2c5454c21952bc74ae3`.

`src/window-handoff-frame-v2.ts` implements pure values and incremental decoding. It is not imported by the CLI, Promise client or a native transport. The existing local JSON parser and watch schema supply strict duplicate-key, number-spelling, UTF8 and tuple validation. RPC body bytes are copied once into owned storage and retained for encoding; decoding never reserializes them.

The header is exactly 21 bytes: RW/version2/tag/body length UInt32LE, raw UTC deadline UInt64LE, relative maximumWaitMs UInt32LE, purpose byte. Body length is 1..4096; maximum frame length is 4117. Client tags are hello/ready/request, host tags welcome/ready_ack/reply/watch_lost/session_ended. Unknown tags, opposite direction, v1 and mixed versions seal the stream. Request tag16 requires positive safe raw UTC and purpose1/request cap1..120000 or purpose2/cleanup cap1..30000. Other tags require zero metadata. Body kind and purpose must agree, and request Wait cannot exceed the original body's deadline.

Every feed, including an empty feed, supplies a snapshot of raw UTC, monotonic time and the private clock-domain object. The decoder fixes the first header-byte observation, keeps the maximum raw observation while that header is incomplete, and rejects prior deadline arrival even after rollback. Header completion validates size, Wait and elapsed budget before allocating a body. The same receive budget covers all body feeds and delayed dispatch via `frame.remaining(point)`. Expiry, invalid domain and monotonic regression are terminal; rollback cannot revive the budget. Fractional remainder below 1ms expires instead of rounding up. A new frame resets its raw peak, so a separate legal cleanup is independent of an older request's observed raw time.

The provider must sample the actual clocks, guarantee buffer ownership through the synchronous copy, supply finite IO/header waits and check remaining time before delayed dispatch. The per-frame receiver cap does not claim measured transit time or simultaneous sender/receiver completion. This module creates neither an authenticated session nor a watch lifetime/signal. Handshake order, session/call correlation, owner tombstones and cancellation ACK gates remain the existing Windows state-model responsibility; they are not reconstructed here.

New tests in `test/window-handoff-frame-v2.test.ts` cover the original fixture, every byte split and one-byte feeds, concatenation, byte/Wait snapshots, multibyte UTF8, raw JSON whitespace, strict header/body/direction rules, partial-header observations, body expiry, delayed-dispatch expiry, fractional remainder, independent rollback cleanup, size limits and EOF sealing. The old client/clock/Windows suites are not rerun. Tests use injected clocks and bytes only: no actual timers, IPC, OS principal, FOX, CDP, public API, notification or release operations.
